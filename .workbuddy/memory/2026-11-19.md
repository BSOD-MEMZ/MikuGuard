# 2026-11-19 — 摄像头始终读不到：ConsentStore 在 24H2 上已失效

## 症状

宿主里插件一切正常（枚举到 2 个摄像头、Toast 身份注册成功），但摄像头真的在被用时
指示点永远不亮、也不报警。用户怀疑是 Windows 更新之后坏的。

## 实测结论（关键，别再走回头路）

机器：Windows 11 24H2 build 26100（补丁到 KB5132061）。

1. **ConsentStore 不再记录桌面程序的摄像头使用**：
   `HKCU\...\CapabilityAccessManager\ConsentStore\webcam\NonPackaged` 下只有旧记录，
   而且 `LastUsedTimeStop` 全都非 0。用 CamProbe 实开摄像头取流（25 秒、真实帧 3264x2448），
   管理员、普通权限（计划任务）、从 explorer 起，三种都试过——**一条新记录都没有**，
   连 Windows 相机 App（UWP）的记录也不更新。
2. **「CreateFile 独占打开设备」判占用也不成立**：摄像头由 FrameServer 服务统一取流，
   客户端进程根本不持有设备句柄（handle64 看 CamProbe 进程，没有任何 `\Device\*` 摄像头句柄）。
   流媒体进行中，用 `dwShareMode=0` + 无权限/0x80/读/读写各种组合打开设备接口，
   **全部成功（err=0）**。所以老 `CameraDeviceBusyProbe` 的判定恒为「空闲」。
3. **正确接口：Media Foundation 传感器活动监控**——`IMFSensorActivityMonitor`
   （`MFCreateSensorActivityMonitor` + `IMFSensorActivitiesReportCallback`）。
   系统在活动变化时回调，报告里有设备 `SymbolicLink`、进程 PID、`GetStreamingState()`。
   实测能同时看到 `F3-B2 CAM → pid 8072`、`SC03 → pid 13888`，和真实占用完全对得上。
   参考实现：`LiuYan-xwx/CameraActivityMonitor`（ClassIsland 插件，用 CsWin32 生成互操作）。

## 改法

- `CameraDeviceBusyProbe` 整个重写：静态持有 monitor + 回调，`Start/Stop/Snapshot`，
  回调里把「设备 → 正在取流的 PID 列表」整体替换进字典（报告是当前活动快照）。
  `Stop` 调 `monitor.Stop()` 必须放在锁外，否则可能和回调抢同一把锁死锁。
- 互操作用 `Microsoft.Windows.CsWin32 0.3.275`（`NativeMethods.txt` 列 5 个 API），
  `PrivateAssets=all`，生成的类型是 `internal`、只活在 MikuGuard.dll 里，不增加包体依赖。
- `CameraGuardService`：轮询直接读 `Snapshot()`，PID→`AppIdentity`（桌面取 exe 路径，
  WindowsApps 下的取包族名），设备 id 和设置精确匹配（`StrictDevice` 不再需要试开缓存）。
  剔除宿主自己 PID（预览窗口）。MF 起不来时才退回 ConsentStore。
- 设置页「测试设备判定」改为显示当前该设备是否活动、PID 列表。

## 验证

- `tools/SensorProbe`（直接编译插件里的 CameraDeviceBusyProbe.cs）：CamProbe 占 SC03 时
  快照正确列出两台设备和 PID。
- 真宿主：部署后启动 ClassIsland.Desktop，日志出现
  `[sensor] Media Foundation 摄像头活动监控已启动`、`[guard] 触发告警：WindowsCamera / F3-B2 CAM`。

## 坑

- `ClassIsland.PluginSdk` 的 cipx 目标会调 `pwsh generate-md5.ps1`；构建机 PATH 里没有 pwsh 时
  报 MSB3073 退出码 9009。**pwsh 必须在 PATH 上**（本机已把 `C:\Program Files\PowerShell\7` 加进机器 PATH）。
