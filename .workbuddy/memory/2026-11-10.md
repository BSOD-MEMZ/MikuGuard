# 2026-11-10

## MikuGuard：设备级判定 + 忽略名单 + 关闭提醒

**改了什么**

- `Services/CameraDeviceBusyProbe.cs`（新）：DirectShow 试开判定。枚举 CLSID_VideoInputDeviceCategory，
  按 moniker 显示名 / 设备实例 ID 匹配选定摄像头，建 `FilterGraph → CaptureGraphBuilder2.RenderStream(null renderer) → IMediaControl.Run()`。
  起得来 = 该设备空闲；起不来/超时/枚举不到 = 按「被占用」处理（宁可多报）。走独立 STA 线程 + 3s 超时，
  图用完立刻 Stop + RemoveFilter + FinalReleaseComObject。
  注意：`ICreateDevEnum.CreateClassEnumerator` 在无摄像头时返回 S_FALSE(1)，不是 0，要单独判。
- `CameraGuardService`：检测改成两层过滤 —— ①`IsWatched(app)`（原 ShouldAlert）滤掉被忽略的程序；
  ②选定具体设备且 `Monitor.StrictDevice` 时，用试开结果决定是否算「在用」。试开结果按「在用程序集合签名」缓存，
  同一批程序只探一次；`Restart()` 时清缓存，且首次 Poll 改到线程池（探测会阻塞，别挂 UI 线程）。
  Poll 加了 `Interlocked` 重入保护。宿主自身（`Environment.ProcessPath`）从访问记录里剔除，避免预览窗口/探测把自己记成占用者。
- `AlertSettings`：`NotifyOnClosed` / `ClosedTitle` / `ClosedImagePath`。`CameraAlertService.ShowClosed()` 发「危机解除」，
  图用 `Assets/monitoring_off.jpg`。只有 `_alertRaisedThisSession` 为真（本次真的弹过占用提醒）且持续 ≥1s 才发，
  平时关摄像头不打扰。Dismiss 也从「每轮都调」改成「只在变成空闲那一次调」，否则会把刚发的关闭提示撤掉。
- 设置页：监视目标下面加「只提示选定摄像头」开关；程序列表标「已忽略」；诊断区加「测试设备判定」按钮（`ProbeDeviceCommand`，
  结果放独立的 `ProbeText`，不会被每秒刷新的 `LastActionText` 覆盖）。
- README 更新了「是哪台摄像头」原理、已知限制、功能列表。

**待验证（本机没有摄像头，测不了）**

- 双摄机器上用「测试设备判定」确认试开这条路准不准；个别驱动可能不拦第二次打开，
  那样会退化成「任意摄像头都提示」，关掉「只提示选定摄像头」即可。
