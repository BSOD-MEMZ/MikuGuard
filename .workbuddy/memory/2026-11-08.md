# 2026-11-08 — 设置页重做 / 自动化 / 花火 / 发版工具

## 设置页为什么会「不像原生」

宿主自己的设置页是 **`settings-container` + 一行一个 `SettingsExpander`**（Header/Description/Footer），
分组标题用 `TextBlock`（宿主用 `ClassIsland.Controls.IconText`，那是宿主程序集里的类型，插件引用不到）。
之前把 `SettingsExpander` 当「分组卡片」，往 Content 里塞一堆 `Grid ColumnDefinitions="180,*"`，
渲染出来就是嵌套卡片 + 没有行分隔，一眼假。

**FluentAvalonia 2.4.1 有 `SettingsExpanderItem`**（`grep SettingsExpanderItem FluentAvalonia.dll` 命中 5 次，
宿主 `CountDownComponentSettingsControl.axaml` 就在用）。之前记的「没有 SettingsCard」是对的，但 Item 是有的。

- 动态列表（过滤名单 / 正在使用的程序）：`SettingsExpander` 里放 `ItemsControl`，ItemTemplate 直接产
  `fa:SettingsExpanderItem`（控制主题是全局注册的，不在 ItemsControl 里也能拿到样式）。
- 子行末行加 `Classes="has-radius"` 补下方圆角。

## 自动化

- `services.AddAction<TAction, TSettingsControl>()`，行动类要 `[ActionInfo(id, name, glyph, addDefaultToMenu:false)]`
  + 继承 `ActionBase<TSettings>`；设置控件继承 `ActionSettingsControlBase<TSettings>`（有 `Settings` 和 `ChangeActionName`）。
- 菜单树 `IActionService.ActionMenuTree`（`ActionMenuTreeNodeCollection`，按 Name 做 Key），
  `ActionMenuTreeGroup` / `ActionMenuTreeItem<TSettings>(id, name, icon, s => s.X = ...)`。
  重复挂树前先 `root.Contains("组名")` 判一下。
- **OnRevert 的旧值不能放实例字段**：行动实例是瞬态的，按 `ActionSet.Guid|行动Id` 存快照（ConcurrentDictionary）。
- `ClassIsland.Core.Abstractions.Automation.TriggerBase` 也是公开的（`AddTrigger<T>`），这轮没用。

## 花火（thock-maimai）

- 仓库 `https://github.com/wzk112/thock-maimai`：`assets/maimai-fireworks.json` 是参数表，
  `windows/core.h` 是 CPU 侧粒子推进（curve/hermite/gradient + 120Hz 定步长积分），`windows/effect.hlsl` 是渲染。
- **Avalonia 没有逐次绘制的混合模式**，也没有 `ImageBrush.TintColor`（只有 `IExperimentalAcrylicMaterial` 有）。
  着色用 `DrawingContext.PushTransform(旋转) + PushOpacityMask(遮罩, rect) + FillRectangle(纯色)`。
- 原贴图除 1519 是「白+alpha」外都是**不透明黑底**（亮度=形状），拿它当 opacity mask 会得到一个方块。
  所以 `tools/make_hanabi_assets.py` 预烘焙：`mask_1519/mask_2694`（白色+alpha=原亮度）、
  `ring_4862`（rgb 取 4862、alpha=3691亮度×4862亮度）。原贴图不进包体。
- 全屏 = 单独一个**透明置顶** `Window`，`TransparencyLevelHint=Transparent` + Win32
  `WS_EX_TRANSPARENT|WS_EX_NOACTIVATE|WS_EX_TOOLWINDOW` 做鼠标穿透（`GetWindowLongPtrW`）。
- 花心会贴屏幕边（信息岛在最上面），钳进 15%~85% 才不至于大半朵被裁。

## 第七轮：花火为什么「根本不对」+ 字形

### 花火三处硬伤

1. **圆环贴图丢了颜色**：`ring_4862` 是彩色贴图，我却用「白色 tint + alpha 遮罩」画，等于把 RGB 扔了，
   渲染成一块灰盘。自带颜色的贴图必须直接 `DrawImage`，不要再染色。
2. **彩虹光环画成一根 169px 粗笔画** → 屏幕四周彩色边框。原版是 shader 里 0.5~0.8 半径上一圈圈**细条纹**，
   改成 5 圈细环（`HanabiRenderer.Bands`）+ 锥形渐变。
3. **没做混合模式**：原版 D3D 逐 sprite 设 blend（星光/放射 screen、圆环加法、彩虹 alpha），越叠越亮。
   Avalonia 的 `DrawingContext` 没有混合模式，alpha 合成会把大圆环压成一块实心色盘。
   → 用 `ICustomDrawOperation` 拿 Skia 的 canvas 直接画。

### Avalonia / Skia 关键事实

- `ICustomDrawOperation` 的命名空间是 **`Avalonia.Rendering.SceneGraph`**（不是 `Avalonia.Rendering`，
  也不是 `Avalonia.Media`）——是 `_scratch` 里反射 Avalonia.Base 查出来的。
- `ImmediateDrawingContext.TryGetFeature<ISkiaSharpApiLeaseFeature>()` → `lease.SkCanvas`。
- 宿主 SkiaSharp 是 **2.88.9**（AssemblyVersion 2.88.0.0），Avalonia.Skia 11.3.17；插件引用 11.3.6 也能跑
  （和 Avalonia.Base 一样由 PluginLoadContext 统一）。
- 探测「能不能用 Skia」不要用 `AvaloniaLocator.Current`（11.3 已经没有这个成员），
  用 `typeof(ISkiaSharpApiLeaseFeature).Assembly` / `typeof(SKCanvas).Assembly` 是否抛异常。
- **exposure 要乘在 alpha 上，不能乘在颜色上**：没有 HDR，乘颜色再加 clamp 会把整朵花糊成白色。
- 烘焙带颜色的贴图时用 **`max(r,g,b)`** 当亮度，别用 luma：彩色像素 luma 很低
  （紫色 (182,0,236) 只有 55），alpha 会掉到 42%，圆环几乎看不见。

## 第八轮：彩虹光环是「扇形盘」，不是同心环（上一轮我自己改错了）

对照网上那张 maimai 烟花的实拍（键盘上是笔记本，屏幕上是从中心放射出去的彩色楔形块 + 白色四角星）：
**彩虹光环（material 49）= 按角度上色的实心扇形盘**，不是我一厢情愿理解的「一圈圈的环」。

拆 `assets/rainbow.hlsl` 得到的实情：
- `atan2` 近似出角度 → `angle*3` → `frac(angle*3*0.795+0.03)` 当色相 → 一圈重复 **3 个色环**
- 再用 `step(0.56,...)` 之类的阈值从 **5 个调色板颜色**（cb0[6..10]：粉/蓝/黄绿/黄/橙）里挑一个
  → 所以色块边界是**硬的**，一圈约 15 个楔形
- 半径上用 `step(length(uv-.5), .5)` 限制在内切圆里，亮度从圆心往外衰减
- 楔形跟着 `angularVelocity` 自转

实现（Skia）：`SaveLayer` + `CreateSweepGradient`（把 5 色 × 3 环展开成 30 个硬边界 stop）
+ `CreateRadialGradient` 配 `SKBlendMode.DstIn` 做径向渐隐，最后 `RestoreToCount`。

顺带确认贴图结构（数值扫出来的）：
- `maimai_1519` 白 + alpha 的四角星（纯白，没颜色）
- `maimai_2694` 灰度放射光芒（纯灰，没颜色）
- `maimai_3691` **环**：r=0 全黑，r≈60(峰值 240)，r=127 归零
- `maimai_4862` **色轮**：色相随角度变、中心最亮（178,0,240）、r>90 归零
  → material 50 = 3691 × 4862 = 彩色圆环，我原来的烘焙是对的

SkiaSharp 2.88 的 `CreateSweepGradient` 没有「颜色数组 + 位置数组 + tileMode」这个重载，
第四参数是 `SKMatrix`，要传 `SKMatrix.Identity`。

## 第九轮：照 rainbow.hlsl 还原（runtime effect 走不通，改用原语拼）

官方截图 `windows-random-left.png`（960x600，`proof()` 出的）暴露的真结构：
- 一圈 **15 个硬边楔形**（5 色 × 3 环，颜色随时间步进平移）
- 楔形上有**网点（halftone）**——shader 里 `frac(pos*2-1 *64)` 的屏幕空间圆点
- 半径方向还有 `fract(radial*4-2(1-alpha))` 的环带调制（只调**亮度**，不挖洞）
- 中心是白色放射光芒（material 80），整体 ×0.75 alpha，所以是淡彩

正确的还原路线本该是 **SkSL runtime effect**（把 HLSL 逐行翻过去，我确实翻完了）。
结果：**SkiaSharp 2.88.9 里 SKRuntimeEffect 一进 DrawRect 就原生崩溃**
（`SEHException 0x80004005`，连 `half4 main(float2 p){return half4(1);}` 这种极简 shader 都崩，
`ToShader(isOpaque, uniforms)` 和带 `SKRuntimeEffectChildren` 的重载都试过）。这条路放弃。

另注：SkSL 里**没有 `step()`**（编译报 unknown identifier），得自己写
`float stp(float edge, float x){ return x >= edge ? 1.0 : 0.0; }`。

最终用 Skia 常规原语按同一套公式拼：
1. `CreateSweepGradient` + 每帧按 `floor(9t)/5` 平移 stop 位置 → 硬边色带
   （硬边界要「同一位置插两个 stop」，否则渐变会插值成糊的）
2. 32×32 圆点 tile + `SKShader.CreateBitmap(Repeat)`（cell = 屏宽/128）→ 网点，`Plus` 提亮 0.3
3. `CreateRadialGradient` + `DstIn` → 外缘衰减
4. `ClipPath(circle)` + `SaveLayer` 收边，整体 ×0.75

结论：**Avalonia 插件里做不了真正的逐像素 shader**（runtime effect 在这版 Skia 上不可用），
想要 1:1 复刻只能等 SkiaSharp 修，或者自己写 CPU 逐像素。

## 第十轮：把官方渲染的三个差距全补上

1. **色带宽度**：重新走一遍 shader 的阈值链才发现分带不是等宽——
   `step(1.0, y)` 恒为 0（y 是 fract，永远 <1），所以第二段把颜色直接覆盖成 cb7(蓝)，
   真正的分段是 `0.2 / 0.4 / 0.6` 三个阈值 → 橙0.2、黄0.2、黄绿0.2、**蓝0.4（双宽）**。
   cb5(灰) 和 cb6(粉) 都会被后面覆盖掉，实际不出现；官方图里的粉色是 4862 色轮那层给的。
2. **淡彩**：调色板颜色往白里揉 18%（`Pastel()`）。
3. **柔和边缘**：色带单独一层 `SKImageFilter.CreateBlur(radius*0.008)`。
   **关键：网点不能被模糊**，否则 (1-dist)² 的点阵直接糊成一片，所以分成
   外层 SaveLayer（收圆+衰减）→ 内层 SaveLayer（带模糊，只画色带）→ 网点 Plus → DstIn 衰减。

## 第十一轮：条带状的是「放射光芒」，之前被我盖掉了

用户一句「官方是条带状、你这糊成一个圆形」点醒的两个硬错误：

1. **`maimai_2694.png` 是约 30 根细尖刺的放射光芒**（把亮度拉 8 倍才看清；之前 64×64 下采样 +
   沿 0° 单线扫描，把尖刺平均没了，误判成「灰度柔光」）。这就是官方图里条带状的来源。
2. **`material 49`（彩虹光环）的 pixel shader 根本不用 `frame.w`（exposure）**，
   我却在 `Sample()` 里对所有材质都乘了 `2^exposure`，彩虹 alpha 被顶到 1.0；
   结果 screen 混合的尖刺叠在饱和背景上等于没加 → 整个尖刺层被吃掉。

修法：
- `Sample()` 里 `material == 49` 时 gain 取 1
- 彩虹层整体再乘 0.45（shader 里是 `outA = a1*0.75`，a1 只在中段接近 1）
- `material 80` 的 tint **不是白色**，是 colorLo(黄绿)→colorHi(红) 的随机插值，之前写死成白色了

验证手法：给探针加 `--only=80`，只保留某个材质的发射器（**先过滤 Emitters 再 Burst**，
否则粒子里的 emitter 索引会错位），单独看一层。单看 80 就是标准 maimai 放射光芒。

## 第十二轮：并排对比才发现「彩条 / 灰白条交替」

把官方图和自己的渲染裁成同尺寸并排看（`_probe/_vs.png`），一眼就看出差在哪：

- 官方是 **彩色条和灰白条交替**，灰白来自 shader 的 `cb5(0.5,0.5,0.5)`——
  每段色带的后半截被灰白顶掉，所以是 12 段彩 + 12 段灰 = 24 条
- 之前我把这层画成「纯彩色扇形/同心环」，方向就错了
- 另外**网点必须是乘法调制**：我先用了 `Plus`（加法），等于在整块彩虹上加白光，
  颜色被冲成奶白、尖刺也被糊掉。改成 `SKBlendMode.Modulate`（贴图灰度 140~255 之间调制）

最终形态：24 条彩/灰交替的硬边条带（sweep 渐变、stop 随 `floor(9t)/5` 平移）+
网点乘法调制 + 色带层轻微模糊（`radius*0.004`）+ 径向衰减放到 0.82 才开始掉。
整层 alpha ≈ `sample.A * 0.85`（对应 shader 的 `outA = a1*0.75`）。

教训：**反编译出来的 HLSL 个别语句（step/lerp 的方向）读不准时，最快的校准方式是
把官方图裁成同尺寸并排比**，比逐行猜快得多。

## 第十三轮：条纹之间必须有透明空隙

沿官方图的圆弧取亮度剖面（`r=160/260/360`，每 2° 一个采样）才看出来：
**亮暗各占一半**，暗的地方亮度掉到 30/255（基本透明）——所以不是「360° 铺满的条带」，
而是「一条亮、一条空」的栅栏。

现在：30 个槽（15 彩 + 15 灰），每槽只占 50%（`duty=0.5`），剩下是透明；
彩槽按 5 色（粉/橙/黄/黄绿/蓝 = cb6/cb10/cb9/cb8/cb7）轮转，正好 5 色 × 3 圈；
灰条提到 214（接近官方的灰白）。

**通用手法**：看不清结构时，沿圆弧取亮度剖面打成 ASCII，比肉眼盯图准得多。
